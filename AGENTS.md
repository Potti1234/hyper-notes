# Working on hypernotes

This is a hyper-effect app. Before changing it, load the `hyper-effect` skill (and the `foldkit` skill for Foldkit itself); they explain the architecture, the rules and where to find working references. The stack and rules follow hyper-tasks.

- Pages are Foldkit programs whose update loop runs on the server. Keep update and view pure; side effects are Commands. Commands run on the server: no `window`, `document` or `localStorage`.
- Only Messages listed in a page's `ClientMessage` may be bound in its view; typed text goes through `onInput`/`onChange` handlers. A missing one stops the whole page from rendering, and only the server log says why. Re-check permissions and validate browser input in update.
- Wrap independently changing parts of a page in `region(h, { id, deps, render })`, list every Model field the region reads in `deps`, and render exactly one root with `h.Id(<same id>)`.
- Shared data changes only through an operation in `src/app/workspace.ts` (pure: data in, result and data out), run by the `Workspace` service; it checks its input again. Postgres (`postgres.ts`) writes the rows that changed. Add a column in `migrate`, the row mapping and `load` together.
- Page documents are schema-validated block JSON (`src/app/editor/schema.ts`); the schema decode is the sanitizer. The editor is an island (`*.client.ts`, `npm run build:islands`); its edits are pure functions of document and selection (`editor/state.ts`, `editor/text.ts`) with unit tests. Keep pure menu/data logic out of `*.client.ts` (e.g. `editor/menus.ts`) so `creaseui-lint css` sees the classes it owns. A second render of blocks on a page (history preview) uses its own element ids.
- Databases: a page's `database` holds properties and views; rows are its child pages, with values by property id in `Page.values`. Computed values (ID, rollup, formula) come from `withComputed` and are never stored. Database changes are `DatabaseChange` values applied by `applyChange` in `src/app/database.ts`.
- Browser-measured values (column widths, image sizes) reach the server through a public script that dispatches a `CustomEvent`, decoded with an `OnCustomEvent` attribute (see `public/column-resize.js`).
- Popovers, pickers and menus are placed only with `anchoredStyle` (`src/lib/anchored.ts`); `test/overlays.test.ts` fails on anchor positions written by hand, and `npm run check:fresh` opens every overlay in a browser and fails if one is off screen. Focus after a morph goes through `model.focus` and the `FocusElement` client command.
- Form controls are creaseui components: `input`/`textarea` for text, `datePicker` for dates. No native date, time, number, checkbox, file or select controls and no bare `h.input`/`h.textarea` outside src/ui and src/lib (`test/native-controls.test.ts`).
- Views are built only from creaseui components (`src/ui`, listed in `crease.lock.json`) under the `@creaseui/lint` strict preset. Raw elements and app classes are allowed only in the registered adapters: `src/app/view/design.ts` (`box` and friends), `icons.ts`, the block renderer `editor/render.ts` and the editor client files. Classes used from other view modules are declared as literals in `design.ts`. `src/styles.css` holds only theme tokens; component CSS lives in `src/app/view/design.css` (hover styles inside `@media (hover: hover)`).
- Content the demo script enters is marked `isDemo`; keep that flag on anything new it adds, so `demo:clear` can remove it.
- Browser checks: sidebar row buttons appear on hover, so hover the row first. `check:fresh` runs `check.mjs`, then `check-overlays.mjs` and `check-editor.mjs` on the same database, so the main check restores view state the later ones rely on. Restart a local server with `pkill -f "src/mai[n].ts"`.
- Done means: `npm run typecheck`, `npm test`, `npm run lint`, `npm run test:pg` and `npm run check:fresh` pass (Postgres from `npm run db:up`).
- hyper-effect is the published `@hyper-effect/core` and `@hyper-effect/island` packages. Framework changes go to the hyper-effect repository and arrive here as a version bump; don't patch `node_modules`.
