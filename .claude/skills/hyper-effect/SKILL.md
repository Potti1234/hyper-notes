# hyper-effect

hyper-effect runs Foldkit programs on the server. Model, Message, `update`, `view`, Commands and Subscriptions are plain Foldkit; the update loop runs in a server session per open page, the view is rendered on the server, and Datastar in the browser applies the morphs and posts events. There is no client-side state to manage, no API layer, and no JSON contract between front and back: a page is one Foldkit program.

Load the **foldkit** skill as well: everything about Model, Message, update, view, Commands, Subscriptions, Foldkit UI and Story/Scene tests is Foldkit's and documented there. This skill covers what is different on the server.

**Where Foldkit's documentation is in this repository:** there is no vendored `repos/foldkit` here. Foldkit's API docs are the doc comments in `node_modules/foldkit/dist/**/*.d.ts` (for example `subscription/keyBindings.d.ts`, `command/index.d.ts`, `dom/dom.d.ts`), and Foldkit UI's in `node_modules/@foldkit/ui/dist`. crease/ui's sources are in the crease repository (`../crease/src/ui`, `src/lib`).

## How to approach the work

- **Start from a working page.** `apps/starter` (generated by `npm run create`) is the smallest complete app; `examples/admin` is a business app (lists, filters, forms, uploads, roles, conflicts, Postgres); `examples/dispatch` is live collaboration (shared state, presence, islands, regions at scale). Pattern-match against them before inventing anything. File pointers by task are in [references/patterns.md](references/patterns.md).
- **One page = one program.** A page has its own `Model`, `Message`, `ClientMessage`, `flags`, `init`, `update`, `view` and `program`, in `src/app/<page>/page.ts`, mounted in `src/main.ts` with `Hyper.layer(program, { ...options, path })`. Shared state between users lives in services (stores) with a change feed, never in a page.
- **The architecture is not optional.** update and view stay pure; side effects are Commands; data arriving from outside is a Subscription. No module-level mutable state in pages, no reading the clock or random in update, no `window`/`document` anywhere on the server.
- **Make it work in a browser, not just in tests.** A page is done when `npm run typecheck`, `npm test` and the browser check (`npm run check` against `npm start`) pass, and you have looked at it.

## A page in brief

```ts
export const Model = S.Struct({ user: S.String, items: S.Array(Item), draft: S.String, error: S.NullOr(S.String) })
export const Message = defineMessageUnion({
  ChangedDraft: { text: S.String },          // typed text: through onInput, never posted as a token
  Submitted: {},                              // a click/submit: a ClientMessage
  GotItems: { items: S.Array(Item) },         // from a Subscription: a server fact
  SucceededAdd: {},                           // a Command result: a server fact
})
// What a browser may post directly. Everything else cannot be forged.
export const ClientMessage = S.Union([Message.Submitted])

export const program: Program<Model, Message, ClientMessage, Flags, Store> = {
  name: 'items',                              // URL segment and snapshot key: unique per app
  Model, ClientMessage,
  flags: request => Effect.gen(function* () { /* authenticate, load */ }),   // PageRedirect / PageNotFound
  init, update, view, subscriptions,
  snapshotDeps: model => [model.draft],       // the session's own state; shared data comes back via Subscriptions
}
```

The full skeleton with Commands, a Subscription on a store and regions is `apps/starter/src/app/tasks/page.ts`; the API is in [references/api.md](references/api.md).

## Rules that keep pages correct

1. **Bind only `ClientMessage`s in views.** `h.OnClick(Message.X())` renders a token the browser posts back; a Message outside `ClientMessage` fails the render. Command results and Subscription Messages must never be in `ClientMessage`.
2. **Never trust what the browser posts.** A user can post any `ClientMessage` with any payload: re-check permissions and validate payloads in update (roles, ownership, ids that must exist), exactly as for an HTTP API.
3. **Typed text goes through handlers.** `onInput`/`onChange` (crease `input`, `h.OnInput(f)`) bind function handlers. Such inputs are *client-owned*: the morph never overwrites what the user types; the server patches the value only when the Model diverges from what the browser sent (for example, clearing the field after save). Do not put typed text into a `ClientMessage`.
4. **Regions: `region(h, { id, deps, render })`.** Wrap every part of a page that changes independently. `render` returns one element with `h.Id(id)`. `deps` must include every Model value the region's view reads (compared by value); outside production a region whose deps miss something fails to render with the field to add. Nested regions need their parent's deps to cover them. Lists: a region per row, inside a region for the list.
5. **`shared: true` only for markup identical for every user.** A shared region renders once per deps for all sessions; it may bind Messages only, and must not read the user or any session state (development checks this across sessions).
6. **Commands run on the server.** No browser globals. Browser effects (focus, scroll, URL replace, navigation) are forwarded via `clientCommands`. Commands whose effects must not happen twice (payments, emails) need idempotency: an event is applied once, but a Command in flight dies with its process. **Before building anything browser-only, read [references/browser.md](references/browser.md):** keyboard shortcuts, focus, drag and drop, menus and dialogs each have a known way.
7. **The Model must be Schema-encodable.** It is snapshotted as JSON (restarts, failover): no functions, class instances, `File`s or Effects in it. Keep references (ids) and load the rest.
8. **Flags authenticate and authorize.** Fail with `PageRedirect` (to /login) or `PageNotFound`; set `principal` in options so a session belongs to its user and ends when they sign out.
9. **Shared data comes from stores with a change feed**, delivered by a Subscription. Build the Message once per change for all sessions with `memoizeLast`; throttle high-churn feeds with `sampleLatest`.

More pitfalls, each found the hard way: [references/gotchas.md](references/gotchas.md). Browser-only behaviour and how to get it: [references/browser.md](references/browser.md).

## Workflow

1. **New app:** `npm run create -- <name> [--title "Title"]` at the monorepo root, then `npm install`. It goes to `apps/<name>` with sign-in, a live page, a store, crease/ui components, Story and HTTP tests and a browser check.
2. **New page:** copy the shape of `apps/starter/src/app/tasks/page.ts`; add a store service if it has shared data; mount it in `main.ts` with a unique `name` and a `path` (`/things/:id` gives `request.params.id` in flags).
3. **UI:** crease/ui components are copied in (`src/ui`, behaviour in `src/lib`). More components: copy them from `examples/admin/src/ui` or `examples/dispatch/src/ui` (which have alert, badge, empty, field, native-select, pagination, table, textarea, toggle-group, …) together with their `src/lib` helper, or from the crease repository. Plain `h.*` elements with Tailwind classes are fine too.
4. **Browser-only behaviour:** check [references/browser.md](references/browser.md) first. Keyboard shortcuts are `keyBindings(h, [...])`, focus is a forwarded Command, drag and drop between server-rendered targets binds natively. Only widgets that need the DOM itself (maps, canvas, rich editors, drag previews) are islands: Foldkit programs running in the browser inside the page.
5. **Test:**
   - update with Foldkit's `Story` (pure; resolve Commands by hand), the view with `Scene`;
   - the page over HTTP with `@hyper-effect/core/testing` (`serve(program, options, store, servicesLayer)`, `openPage`, `postEvent`, `openStream`, `readUntil`, `token`). Pass the page's `path` in `options` for anything but `/`. The stream's first event is the whole page, so wait for text that only appears after your change;
   - Story tests resolve every Command, forwarded ones included (a focus Command after a shortcut); test the logic with an inner update if a wrapper adds such Commands;
   - extend `scripts/check.mjs` (Playwright) with every feature: only a browser shows morphs, focus and typing while the page updates.
6. **Run:** `npm start` (development: markup validation and region checks on; 3–10× slower than production). Measure only with `NODE_ENV=production`.

## Done checklist

- [ ] `npm run typecheck`, `npm test`, `npm run check` pass; no errors in the server log or the browser console.
- [ ] Every view-bound Message is in `ClientMessage`; update re-checks permissions for each.
- [ ] Every changing part is a region with complete deps (development renders would fail otherwise; open every state of the page once).
- [ ] No browser globals in Commands; forwarded browser effects are in `clientCommands`.
- [ ] Model is plain data; `snapshotDeps` names the session's own state.
- [ ] Looked at the page in a browser, in two windows if it has shared data.
